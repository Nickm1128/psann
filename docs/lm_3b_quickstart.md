# Larger LM runs

Start with the [small LM workflow](lm.md) and validate tokenizer identity, checkpoint reconstruction, and the chosen CUDA runtime before scaling. The [larger configuration](../examples/lm/configs/waveresnet_3b_fsdp.yaml) preserves its declared model dimensions and `ddp: auto` setting. Its filename is a historical experiment identifier, not a guarantee of parameter count or sharding mode. Count actual parameters for the resolved vocabulary/configuration and select the required distributed settings explicitly. Replace the two tokenizer path placeholders with your trained tokenizer bundle. Generate the tiny corpus as described in the [LM example index](../examples/lm/README.md), or set the intended corpus path before running.

Use `python -m psannlm train --help` for streaming corpus and distributed training options. Choose `--architecture wave` or provide a complete canonical `--model-config`. Keep dimensions, tokenizer assets, data manifest, accumulation, precision, and process topology explicit. Run with the hardware required by the configuration; a single-device smoke does not validate a physical multi-GPU run.

`tools/build_manifest.py`, `tools/dedupe.py`, and `tools/decontaminate.py` provide source-checkout corpus utilities. Inspect their help before selecting paths. Save tokenizer vocabulary and special-token mappings with the model artifacts. Export bundles record canonical model configuration; uploading or publishing them is a separate action.
